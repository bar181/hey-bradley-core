The Problem — Cold Starts, Every Time

Your AI woke up this morning
and forgot everything.

Every conversation with an AI starts at zero. The agent that fixed your authentication bug yesterday doesn’t remember doing it today. The pattern it discovered? Gone. The architectural decision it learned from three failed attempts? Evaporated.

Traditional databases can store text, but they can’t search by meaning. You can look up “JWT refresh token” by keyword, but you can’t ask “how did we solve the session expiry problem?” and get the right answer in sub-millisecond time.

Without semantic memory, every AI session is a cold start. Agents repeat the same research, make the same mistakes, and never compound their knowledge.

The Guide — RuVector Enters

What if the database got smarter
every time you searched it?

Most vector databases are static indexes. You insert vectors, you search vectors. The index never improves on its own. RuVector is different.

RuVector wraps HNSW (Hierarchical Navigable Small World) graphs with Graph Neural Networks that learn from every query. Each search teaches the index what “similar” actually means in your project’s context. The edges between vectors grow learnable weights. The graph reorganizes itself to surface better results faster.

It’s not just a database. It’s a living neural architecture that turns static embeddings into compounding intelligence.

The Plan — How RuVector Works

Four layers of intelligence.

1

Embed

Convert text, code, or patterns into high-dimensional vectors using ONNX models (MiniLM-L6 or MPNet). Supports Euclidean and Poincaré (hyperbolic) geometries.

2

Index with HNSW

Vectors are inserted into a Hierarchical Navigable Small World graph. O(log n) search complexity, navigable skip-list structure, and tunable M/efConstruction parameters.

3

Learn with GNN

Graph Neural Networks add learnable edge weights to the HNSW graph. Every query teaches the index what “similar” means in context. Message-passing layers propagate relevance signals.

4

Retrieve & Adapt

Semantic search returns the most relevant results. EWC++ prevents catastrophic forgetting. SONA provides instant adaptation without full retraining.

Architecture — The Stack

Rust core. JavaScript surface.

RuVector is written in Rust for performance, with TypeScript/JavaScript bindings via npm. It runs as a library, a WASM module (browser/IoT), a CLI, a PostgreSQL extension, or a containerized service.

Key Features

What makes RuVector different.

Self-Learning HNSW

Graph Neural Networks add learnable weights to HNSW edges. The index improves with every query — no manual tuning required.

Hyperbolic Geometry

Poincaré ball embeddings capture hierarchical relationships that Euclidean space cannot represent. Code → module → function hierarchies map naturally.

50+ Attention Mechanisms

FlashAttention-3, multi-head, cross-attention, and sparse attention variants. Choose the right attention pattern for your data.

Hybrid Search

Combines dense vector similarity with sparse keyword retrieval and Graph RAG for maximum recall and precision.

Multi-Platform

npm package, WASM (browser/IoT), CLI, PostgreSQL extension, or Docker container. RVF format boots in 125ms with zero dependencies.

EWC++ Memory Guard

Elastic Weight Consolidation prevents catastrophic forgetting. New patterns don’t erase old knowledge — the system accumulates intelligence over time.

How-To Guide — Quick Start

From install to semantic search
in four steps.

1. Install

# npm package npm install ruvector # Or with the LLM runtime npm install @ruvector/ruvllm

2. Create an Index

import { RuVector } from 'ruvector'; // Create a new HNSW index const db = new RuVector({ dimensions: 384, // MiniLM-L6 dimension metric: 'cosine', // cosine, euclidean, or dot maxElements: 100000, // max vectors efConstruction: 200, // build quality (higher = better) M: 16, // connections per node }); await db.init();

3. Insert Vectors

// Single insert await db.insert({ id: 'auth-pattern-1', vector: embedding, // Float32Array[384] metadata: { type: 'pattern', domain: 'authentication', description: 'JWT refresh token with sliding window' } }); // Batch insert (52K+/sec) await db.batchInsert(vectors);

4. Search by Meaning

// Semantic search const results = await db.search({ vector: queryEmbedding, topK: 5, filter: { type: 'pattern' } // optional metadata filter }); // Results ranked by semantic similarity results.forEach(r => { console.log(r.id, r.score, r.metadata.description); });

In Practice — What Gets Stored
