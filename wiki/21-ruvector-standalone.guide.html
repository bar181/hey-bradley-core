What Is RuVector

Not just a vector database.
A living neural architecture.

RuVector is a Rust-powered vector database with JavaScript/TypeScript bindings. It implements HNSW (Hierarchical Navigable Small World) graphs for approximate nearest-neighbor search — the same algorithm behind Pinecone, Qdrant, and pgvector.

What makes RuVector different: the HNSW graph has learnable edge weights powered by Graph Neural Networks. Every query teaches the index what “similar” means in your specific context. The paths that produce good results get stronger. The index reorganizes itself continuously. Search quality improves 50–80% over time with zero code changes.

It runs everywhere: npm package, WASM module (browser, IoT, embedded), PostgreSQL extension (pgvector drop-in replacement), CLI, or Docker container.

Core Features

What you get out of the box.

HNSW Indexing

O(log n) approximate nearest-neighbor search. Tunable M (16–64 connections), efConstruction (100–400), efSearch (50–500). Navigable multi-layer graph structure.

GNN Self-Learning

Graph Neural Networks add learnable weights to HNSW edges. Message-passing layers propagate relevance signals. Search improves 50–80% over time.

Hyperbolic Geometry

Poincaré ball and Lorentz hyperboloid models. Möbius operations for hierarchical data. Captures tree-like structures that Euclidean space cannot represent.

Hybrid Search

Dense vector similarity + sparse keyword retrieval + Graph RAG. Maximum recall and precision in a single query.

50+ Attention Types

FlashAttention-3, multi-head, cross-attention, local-global (Longformer), hyperbolic attention, RoPE, MoE routing, sparse attention, and more.

EWC++ Memory Guard

Elastic Weight Consolidation prevents catastrophic forgetting. New patterns don’t erase old knowledge. Intelligence accumulates over the lifetime of the index.

Quantization

Scalar (4x compression), Product (8–16x), Binary (32x). Trade memory for accuracy at scale. BitNet 1.58-bit with TL1 kernels.

Multi-Metric

Cosine similarity, Euclidean distance, dot product, Manhattan distance. Choose the right distance metric for your embedding model.

Query Languages

SQL, SPARQL, and Cypher via rvLite unified query interface. Graph, RDF, and relational paradigms in one engine.

Developer Guide — Step by Step

From install to semantic search.

1

Install the Package

RuVector is available on npm. The Rust core compiles to native bindings automatically.

# Install core package npm install ruvector # Or with the LLM runtime npm install @ruvector/ruvllm # Or the PostgreSQL CLI npm install -g @ruvector/postgres-cli
2

Create an HNSW Index

Initialize with your embedding dimensions and distance metric. Tune HNSW parameters for your use case.

import { RuVector } from 'ruvector'; const db = new RuVector({ // Required dimensions: 384, // Must match your embedding model // Distance metric distanceMetric: 'cosine', // 'cosine' | 'euclidean' | 'dotproduct' | 'manhattan' // HNSW tuning m: 32, // Connections per node (16-64, default 32) efConstruction: 200, // Build quality (100-400, higher = better index) efSearch: 100, // Search quality (50-500, higher = more accurate) maxElements: 100000, // Maximum vector capacity // Storage storagePath: './data/vectors', // Persist to disk (optional) }); await db.init();
3

Insert Vectors

Insert single vectors or batch insert at 52K+ vectors/second. Attach metadata for filtered search.

// Single insert with metadata await db.insert({ id: 'doc-001', vector: embedding, // Float32Array matching dimensions metadata: { type: 'article', topic: 'machine-learning', date: '2026-04-07', } }); // Batch insert (52K+ vectors/sec) const vectors = documents.map((doc, i) => ({ id: `doc-${i}`, vector: doc.embedding, metadata: { title: doc.title, category: doc.category } })); await db.insertBatch(vectors);
4

Search by Meaning

Semantic similarity search with optional metadata filters. Results ranked by distance score.

// Basic semantic search const results = await db.search({ vector: queryEmbedding, // Your query vector topK: 10, // Number of results }); // Filtered search const filtered = await db.search({ vector: queryEmbedding, topK: 5, filter: { category: 'machine-learning', // Metadata filter } }); // Process results results.forEach(result => { console.log(result.id); // 'doc-042' console.log(result.score); // 0.9847 (similarity) console.log(result.metadata); // { type: 'article', ... } });
5

Enable GNN Self-Learning

Turn on the Graph Neural Network layer. The index starts learning from every query automatically.

// Enable GNN on the index await db.enableGNN({ learningRate: 0.001, // How fast edges adapt ewcLambda: 0.4, // EWC++ strength (prevents forgetting) messagePassingLayers: 2, // GNN depth }); // The index now learns from every search // Paths that produce good results get stronger // Search improves 50-80% over time, automatically // Check learning stats const stats = await db.gnnStats(); console.log(stats.queriesProcessed); console.log(stats.edgeWeightRange); console.log(stats.improvementPercent);
6

Hyperbolic Embeddings (Optional)

Use Poincaré ball geometry for hierarchical data. Taxonomies, org charts, and code module trees map naturally.

// Create index with hyperbolic geometry const hyperDB = new RuVector({ dimensions: 384, geometry: 'poincare', // Poincaré ball model curvature: -1, // Negative curvature for hyperbolic space maxNorm: 0.99999, // Keep vectors inside the ball }); // Möbius operations for geodesic distances // Naturally captures parent-child, category-item relationships // More expressive than Euclidean for tree-structured data
7

Persist and Load

Save the index to disk (including GNN weights). Reload instantly. RVF format boots in 125ms.

// Save to disk await db.save('./my-index.rvf'); // Load from disk (125ms cold boot) const loaded = await RuVector.load('./my-index.rvf'); // RVF format includes: // - HNSW graph structure // - GNN learned weights // - All metadata // - WASM runtime (portable across platforms)
GNN Self-Learning — How It Works

Static indexes are yesterday.
Living graphs are now.

Traditional HNSW builds a fixed graph at insert time. The structure never changes after creation. RuVector adds a Graph Neural Network layer that makes the graph adaptive.

Message Passing

GNN layers propagate relevance signals across the HNSW graph. When a search traverses an edge and the result is used, that edge gets a stronger weight. Unused paths weaken over time.

Learnable Edge Weights

Every HNSW edge has a trainable weight parameter. The graph learns which connections actually matter for your specific data distribution and query patterns.

EWC++ Protection

Elastic Weight Consolidation prevents catastrophic forgetting. When the index learns new patterns, it protects the weights that encode important old knowledge. Intelligence accumulates.

SIMD Acceleration

The entire learning loop executes in <1ms via Rust SIMD intrinsics. No separate training step. No batch jobs. Learning happens inline with every query.

HNSW Configuration Reference

Tuning the index.

HNSW performance depends on three key parameters. Here’s how to tune them for your use case.

Parameter Range Default Effect
M 16 – 64 32 Connections per node. Higher = better recall, more memory
efConstruction 100 – 400 200 Build-time quality. Higher = better index, slower insert
efSearch 50 – 500 100 Search-time quality. Higher = more accurate, slower query
maxElements 1 – millions 10,000 Pre-allocated capacity. Set to expected max for best perf

Quantization Options

Type Compression Quality Loss Use Case
None 1x (full precision) 0% Maximum accuracy, small datasets
Scalar 4x <1% Good balance, most use cases
Product 8–16x 1–3% Large datasets, memory constrained
Binary 32x 5–10% Massive scale, rough filtering

Distance Metrics

Cosine

Best for text embeddings. Direction matters, magnitude doesn’t.

Euclidean

Spatial distance. Best for image features, physical coordinates.

Dot Product

Raw similarity. Best when magnitude encodes importance.

Manhattan

Grid distance. Useful for categorical and sparse data.

CLI

Command-line interface for database management, vector operations, and schema migrations.

Universal binary container. Merges database, models, GNN state, WASM runtime into one deployable file. 125ms cold boot.

await db.save('index.rvf') // Ships as one file, runs anywhere

Docker

Containerized service with REST API. Production-ready with health checks, metrics, and horizontal scaling.

docker run -d -p 5432:5432 \ ruvnet/ruvector-postgres

PostgreSQL Integration

Drop-in pgvector replacement.

RuVector’s PostgreSQL extension adds GNN self-learning to standard vector operations. Existing pgvector queries work unchanged — you just get a smarter index.

-- Start the Docker container docker run -d --name ruvector \ -e POSTGRES_PASSWORD=secret \ -p 5432:5432 \ ruvnet/ruvector-postgres:latest
-- Create a vector table (standard pgvector syntax) CREATE TABLE documents ( id SERIAL PRIMARY KEY, title TEXT, embedding vector(384) ); -- Create HNSW index with GNN learning CREATE INDEX ON documents USING hnsw (embedding vector_cosine_ops) WITH (m = 32, ef_construction = 200); -- Search (same syntax as pgvector) SELECT id, title, embedding <=> '[0.1, 0.2, ...]' AS distance FROM documents ORDER BY embedding <=> '[0.1, 0.2, ...]' LIMIT 10; -- RuVector-specific: check GNN learning stats SELECT * FROM ruvector_gnn_stats();
Use Cases

Where RuVector excels.

RAG Systems

Retrieval-augmented generation with semantic search. The index learns which documents are actually useful for which queries — retrieval improves automatically over time.

Agent Memory

Persistent semantic memory for AI agents. Code patterns, architectural decisions, outcomes. EWC++ ensures old knowledge survives new learning.

Recommendation Engines

User preference vectors, content embeddings, collaborative filtering. Hyperbolic geometry captures hierarchical category structures naturally.

Semantic Code Search

Embed functions, classes, and modules. Search by intent, not keywords. “How do we handle auth?” finds the right code even if it never mentions “auth.”

Anomaly Detection

Security fingerprints, log patterns, network traffic. Vectors that don’t cluster with any known pattern are flagged. GNN learns what “normal” means in your system.

Edge / IoT

3MB WASM module runs on embedded devices. Local vector search without cloud connectivity. Binary quantization for extreme memory constraints.
