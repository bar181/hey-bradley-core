Ruflo v3.5 — Hooks System

Compact & Post-Compact Hooks

How Ruflo preserves context across Claude Code's compaction boundary using PreCompact, micro-compaction patching, and memory bridge injection.

1. Why Compaction Hooks Exist

Claude Code operates in a finite context window. When the conversation approaches this limit, the system compacts prior messages—summarizing them into a condensed form. Compaction irreversibly discards:

  • Exact file paths edited, bash commands run, grep results
  • Decision reasoning—why a particular approach was chosen
  • Code snippets discussed, error messages diagnosed
  • Multi-step workflow sequences and agent coordination state

Ruflo's compact hooks solve this by capturing context before compaction and restoring it after, creating an "infinite context" bridge (see ADR-051).

2. Claude Code's Two Compaction Mechanisms

Micro-Compaction (Vd function)

Runs silently on every query. Targets tool results only:

Micro-Compact Rules (Hardcoded in cli.js)
ParameterValueMeaning
Ny540,000Minimum total tool-result tokens to activate
qy520,000Minimum token savings required
Ly53Keep last N tool results intact

Tools affected: Read, Bash, Grep, Glob, WebSearch, WebFetch, Edit, Write. Old results become [Old tool result content cleared].

Full Compaction (Auto or Manual)

Fires when context exceeds threshold. Summarizes the entire conversation. Triggers the PreCompact hook with:

  • transcript_path — Full JSONL transcript of the conversation
  • session_id — Current session identifier
  • trigger — "manual" (user typed /compact) or "auto" (context limit hit)

3. Hook Configuration in settings.json

Ruflo registers two PreCompact matchers—one for manual, one for auto:

"PreCompact": [
  {
    "matcher": "manual",
    "hooks": [
      { "type": "command", "command": "node hook-handler.cjs compact-manual" },
      { "type": "command", "command": "node hook-handler.cjs session-end", "timeout": 5000 }
    ]
  },
  {
    "matcher": "auto",
    "hooks": [
      { "type": "command", "command": "node hook-handler.cjs compact-auto" },
      { "type": "command", "command": "node hook-handler.cjs session-end", "timeout": 6000 }
    ]
  }
]

Both matchers also call session-end to consolidate the intelligence graph before context is lost.

4. What Each Hook Does

PreCompact → compact-manual / compact-auto

Execution Steps
  1. Read transcript — Parse the JSONL transcript from transcript_path
  2. Chunk & hash — Split conversation into chunks, compute content hashes for dedup
  3. Summarize — Extract key decisions, file paths, code context (local, no LLM call)
  4. Store to AgentDB — Write chunks to the memory backend with hash-based embeddings
  5. Export patterns — Save intelligence patterns to compact-patterns.json

The manual vs auto distinction allows different strategies: manual compaction can take more time (user-initiated), while auto compaction must stay within the 6s timeout.

PreCompact → session-end

Intelligence Consolidation
  1. Consolidate intelligence graph — Merge pattern entries, recompute PageRank across edit and task nodes
  2. Persist session state — Save session metrics (edits, tasks, agent spawns) to disk
  3. Flush memory — Ensure all pending memory writes are committed

5. Post-Compact: Context Restoration

After compaction completes, Claude Code fires SessionStart with source: "compact". Ruflo's session-restore hook then:

  1. Detects post-compact context — Checks if this is a fresh start or post-compaction resume
  2. Retrieves archived context — Queries AgentDB for the most relevant stored chunks using HNSW vector search
  3. Injects via additionalContext — Returns up to 4,000 chars of restored context that gets woven into the new compacted conversation
  4. Reinitializes intelligence — Reloads the pattern graph so routing and learning continue seamlessly
BEFORE COMPACTION
  context window filling up...
  ↓
PreCompact fires (trigger: auto|manual)
  ↓  hook-handler.cjs compact-auto
  ↓    → read transcript, chunk, hash, store to AgentDB
  ↓  hook-handler.cjs session-end
  ↓    → consolidate intelligence, persist state
  ↓
Claude Code compacts (conversation summarized)
  ↓
SessionStart fires (source: "compact")
  ↓  hook-handler.cjs session-restore
  ↓    → query AgentDB, inject additionalContext
  ↓    → reload intelligence graph
  ↓
AFTER COMPACTION — context restored, session continues

6. Aggressive Micro-Compaction (Prevention)

Ruflo also patches the micro-compaction threshold to delay or prevent full compaction entirely:

Strategy: CLAUDE_AUTOCOMPACT_PCT_OVERRIDE=50

By default, micro-compaction only activates at ~80% context usage. Ruflo sets the override to 50%, which:

  • Activates pruning at ~45% instead of ~80%
  • Keeps context lean through early, aggressive pruning of old tool results
  • Reduces frequency of full compaction events significantly

Additionally, Ruflo's SDK patch inserts _aggressiveTextPrune() after the standard Vd() call to also prune old conversation text, not just tool results.

7. Design Principles

PrincipleImplementation
Hook-NativeUses only official Claude Code PreCompact and SessionStart events
Timeout-SafeAll ops complete within 5-6s using local I/O, no LLM calls
Dedup-AwareContent hashing prevents re-storing on repeated compactions
Budget-ConstrainedRestored context capped at 4,000 chars to avoid flooding
Non-BlockingHook failures exit 0—compaction always proceeds
Backend-AgnosticWorks with SQLite, AgentDB, RuVector PostgreSQL, or JSON
