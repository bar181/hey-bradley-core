The Plan — How RuFlo Works

Four layers. One coordination surface.

Every complex task flows through the same pattern: initialize the swarm, spawn specialized agents, coordinate through shared memory, synthesize results. RuFlo handles the plumbing so agents focus on the work.

1

Initialize the Swarm

Choose a topology — hierarchical for tight coordination, mesh for peer-to-peer, adaptive for dynamic scaling. The queen agent takes control.

2

Spawn Specialized Agents

A coder writes code. A tester writes tests. A reviewer checks quality. A security-architect audits for vulnerabilities. Each agent has one job and does it well.

3

Coordinate via Memory

HNSW-indexed vector memory gives every agent access to shared context. No agent works blind. Patterns learned on one task accelerate the next.

4

Synthesize & Ship

Results converge. Hooks fire automatically — linting, testing, pattern recording. The final output is reviewed, committed, and deployed.

How-To Guide — Getting Started

From zero to swarm in five commands.

1. Install & Connect

Add RuFlo as an MCP server to Claude Code. Start the daemon.

# Add RuFlo as MCP server claude mcp add ruflo -- npx -y @claude-flow/cli@latest # Start background workers npx ruflo@latest daemon start # Verify everything works npx ruflo@latest doctor --fix

2. Initialize a Swarm

Choose your topology and spawn the coordinator.

# Hierarchical swarm with 8 agents (recommended for coding tasks) npx ruflo@latest swarm init --topology hierarchical --max-agents 8 --strategy specialized # Check status npx ruflo@latest swarm status

3. Spawn Agents

Spawn specialized agents for your task. Each agent type has a focused role.

# Spawn a coder agent npx ruflo@latest agent spawn -t coder --name feature-coder # Spawn a tester agent npx ruflo@latest agent spawn -t tester --name test-writer # Spawn a reviewer agent npx ruflo@latest agent spawn -t reviewer --name quality-check

4. Use Memory

Store and search patterns across sessions. HNSW indexing makes search 150x faster.

# Store a pattern npx ruflo@latest memory store --key "auth-pattern" --value "JWT with refresh tokens" --namespace patterns # Semantic search npx ruflo@latest memory search --query "authentication" --namespace patterns # List all stored knowledge npx ruflo@latest memory list --limit 20

5. Run Diagnostics

The doctor command catches problems before they become emergencies.

# Full system health check npx ruflo@latest doctor --fix # System status overview npx ruflo@latest status # Agent health check npx ruflo@latest agent health
Intelligence — 3-Tier Model Routing

The right brain for the right job.

Not every task needs the biggest model. RuFlo’s ADR-026 routing system automatically selects the cheapest, fastest model that can handle the job.

Tier 1 — WASM

<1ms latency · $0 cost
  • Simple transforms (var→const)
  • Type annotations
  • Format corrections
  • Agent Booster handles it

Tier 2 — Haiku

~500ms latency · $0.0002
  • Simple tasks (<30% complexity)
  • Routine code generation
  • Basic analysis
  • Standard formatting

Tier 3 — Sonnet/Opus

2-5s latency · $0.003-0.015
  • Complex reasoning (>30%)
  • Architecture decisions
  • Security audits
  • Cross-file refactors

RuVector — The Memory Engine

HNSW: How agents remember.

RuVector is the vector search engine inside RuFlo. It uses Hierarchical Navigable Small World (HNSW) graphs to find similar patterns in sub-millisecond time — even across millions of stored memories.

What it stores

  • • Code patterns and architectural decisions
  • • Agent outcomes (success/failure + context)
  • • Cross-session conversation state
  • • Learned optimizations and routing preferences
  • • Security vulnerability fingerprints

Why it matters

  • • 150x faster search vs. linear scan
  • • Semantic search, not just keyword matching
  • • Namespace isolation between projects
  • • EWC++ prevents catastrophic forgetting
  • • Quantization for 4-32x memory reduction
