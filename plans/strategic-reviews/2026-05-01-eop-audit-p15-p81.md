## §3. Acceptance rationale per gap class

**Class A — Pre-process phases (P15-P19):** Preflight pattern was introduced at P20 (see `mvp-plan/STATE.md` §2 + CLAUDE.md "Standard Phase Process"). Backfilling preflight for already-sealed phases is destructive (rewrites historical record). Decision: leave as-is. Triplet is `log+retro` for these five.

**Class B — Sprint G (P39-P43):** Sprint G (Interview Mode) is documented as "deferred to commercial" in `plans/implementation/mvp-plan/STATE.md` and `plans/strategic-reviews/open-core-moat-roadmap.md`. Folders never existed. No backfill required.

**Class C — Sprint H/I wave folders (P44, P45, P47, P48):** Sprint H+I were sealed before the per-phase folder cadence stabilized. STATE rows were backfilled 2026-04-29 with ADR references (ADR-067, ADR-068, ADR-070, ADR-071). The ADRs carry the durable architectural record; the missing folders carry only ceremonial value. Decision: leave as-is; mark as **carry-forward** (low priority) for any future archival pass.

**Class D — Mid-sprint seal phases (P46, P49):** Preflight is intended for *opening* a phase. Sprint-SEAL phases close a sprint and produce a `deep-dive/` review folder instead. Both P46 and P49 follow this pattern (session-log + retrospective + `deep-dive/`). Decision: pattern is correct; preflight not applicable.

**Class E — Mid-Sprint mini-phase (P34):** Phase opened inside an active Sprint E to close UI debt. Preflight folded into session-log §1 with explicit reference. Decision: pattern is acceptable; documented in P34 session-log.

**Class F — P59/P60 missing preflight:** Both phases opened with the preflight folded into session-log §1 (a documented compression for setup-style phases that follow immediately on the prior phase's seal). Git history shows clean partial → seal commits. Decision: acceptable; carry-forward for future setup phases is "preflight-in-session-log §1" pattern.

**Class G — P61 planning-only:** Folder is a planning capture, not a sealed code phase. No `01-... .md` plan-execution split, no code commits attributed to P61 directly (code lived in P61b `8025878` and was rolled into the OC-1..N stream). Decision: triplet not applicable for planning-only phases; pattern documented here.

**Class H — P81 open:** Open phase under sibling-agent ownership at this dispatch. Closure is A2's responsibility per the P82 dispatch brief. Decision: not a gap.
