# Hey Bradley — After-Project Real Talk

> The 2-hour beers-and-pizza version. No headings. No agenda.
> Just the actual story of what happened. — 2026-05-04

---

So here's the thing. We set out to build a website builder that secretly writes enterprise specs in the background. Pour your idea in one end, get a marketing site out the other, and somewhere in the middle a bunch of math-symbol AISP documents would quietly accumulate for the AI agents downstream. That was the pitch in March. It made sense at the time.

Eight months and 109 phases later, we built something different. Not in the bait-and-switch sense — we still have the builder, we still have listen mode, the specs still come out. But the thing we actually shipped isn't a website builder. It's a spec factory. The markdown bundle that falls out the back is the product. The website preview is one of three lenses on the same JSON. And honestly? That's the most important thing that happened during this build.

The reframe didn't come from a planning session. It came from owner Q2 during the P95 sprint, when we were arguing about whether to ship a ZIP file or a markdown bundle for the Claude Code export. Owner picked markdown. One file. File markers between sections. Readable, git-versionable, LLM-ingestible, zero dependencies. That decision changed what the product was. The bundle stopped being a side-effect of building and became the canonical output. Everything after P96 made more sense because of it.

The middle of this build was rough in a few specific places. P19 was rough because real STT on a real microphone is nothing like the simulated transcripts. P58 was rough because we'd promised an RC and the persona scores told us we weren't ready. P101 was the worst — three personas below their floors, Grandma at 84, Framer at 84, Lars at 85, all needing 86. We could have papered over it. The ADR could have rounded up. We didn't. P101 sealed with the floor breaches admitted in writing, and ADR-131 named them out loud. P102 fixed it in one sprint — token migration, Agentics live-wire, status palette tokens — and the next score read 86/86/88. Zero floor breaches at v2.0.0-RC1. That's the discipline working. You name what's broken at the seal, you fix the surface, you re-score against the same rubric. You don't move the goalposts.

The audit at `7778e05` was the other turning point. Five chunks of brutal-honest gap analysis, 1,691 LOC, 77 raw findings, 19 of them P1. It seeded P104 through P109 directly. Most of those phases were 4-to-6 hour shifts that closed two or three audit items each in disjoint-scope agent waves. The pattern was reliable enough that P107 estimated 4-6 hours, ran in 2. P109 estimated 2-3, ran in 1.5. The audit named owners and LOC budgets up front, so the work was trivially scopeable. That's the real productivity unlock — not the agents themselves, but a brutally honest audit that already did the carving.

We got things wrong. P108 caught one of the more embarrassing ones. The audit had grepped for `^\s*test(` to count test cases in `p76-spec-export-quality.spec.ts` and concluded the file was empty. It wasn't. The file had `const it = test;` aliased at the top and 24 cases all using `it()`. We pretended for half a phase that a spec needed rebuilding when it just needed reading more carefully. ADR-136 documents the correction. Future audits should test their own grep patterns. The audit-grep itself is now the bug we look for first.

The other one we got wrong was the `existsSync` test culture. We have 1,038 `existsSync` calls across 131 spec files. About 85% of post-P75 specs are filesystem-read regex matchers, not behavioral tests. They check whether a file exists and whether a string is in it, not whether the surface actually works. P108 added mobile viewport projects and behavioral helper coverage, but the systematic prune of soft-pass guards is still on the carry-forward list. If we did this build again, every spec would require at least one `page.goto` from day one. No exceptions.

The strategic reframe that landed late was the connections layer. We started building the Claude Code plugin as if it were a co-equal product with the web app — same feature surface, same depth, both shipping at parity. Halfway through the connections sprint we realized that wasn't right. The plugin was going to be the discovery surface, not the destination. So we cut scope hard. The plugin generates specs. It does not preview them. Visualization, iteration, the Builder mode, the Listen mode — all of that lives at heybradley.app. By design. The plugin is intentionally incomplete because completion would cannibalize the web app. The pre-launch sprint at `e506913` made that real with funnel CTAs across three surface patterns — a 30-LOC change with strategic weight punching way above its line count.

That's the move that turned the connections layer from a product-cannibalization risk into a top-of-funnel acquisition surface. We're not selling the plugin. The plugin sells the web app. And the web app sells the spec discipline. Three layers, one funnel, each one pointing at the next. The clarity is worth more than the feature breadth would have been.

What did we learn about ourselves? We learned that the multi-hour shift cadence is real. Original phase budgets ran 10 to 50 times conservative once we calibrated against actual velocity. We learned that disjoint-scope parallel agents merge cleanly when you carve by file ownership and let the closer touch only the ADR and the EOP triplet. We learned that brutal-honest reviews are the real flywheel — name what's broken, the next phase scopes itself. We learned that ADR supersession chains are how you keep the past in the room. ADR-057 became ADR-098 became ADR-134, and each one is greppable, each one points at the others. You can read the build by following the ADR pointers.

What would we do differently? Behavioral testing from day one. No `existsSync` documentation tests. The audit-grep self-test discipline — every grep pattern gets tested against known positives and known negatives before it counts as a finding. And the soft-pass culture would never have started if the first ten specs had been required to actually run the surface they describe.

What's still broken? The Connections MCP standalone runtime has an ESM publish-blocker — `tsconfig` `module: ESNext` builds clean but Node's ESM loader needs `.js` extensions on imports. NodeNext fixes it. Not caught in the strict typecheck because strict typecheck doesn't validate runtime resolution. We named it as G5 in the verification doc. Owner closes it before npm publish. There's the Agentic IDE v0 we deferred until we see L3-L5 Cursor signal. There's the live BYOK round-trip that costs five cents and waits on owner. There's HNSW indexing — we have 126 entries in ruvector and zero of them are actually indexed. That activation is Tier-2 commercial work.

So what now? Try it. heybradley.app is the destination. The plugin lives at the npx CLI we shipped. Tell us what's broken. The whole point of waiting for L3-L5 user signal post-launch is that we don't know which carry-forwards matter most until people use the thing. The next chapter waits on the signal. We've done what we can do without users. The rest needs a microphone, a real prompt, and somebody who isn't us trying to ship something with it.

---

Here's the one thing I think we earned the right to say out loud. The discipline that mattered wasn't the swarm. It wasn't the agents. It wasn't the velocity. It was the willingness to admit, at every seal, what wasn't done. P101 sealed with three floor breaches in writing. P104 declared something wired that turned out to have zero callers. P106 deleted 123 lines of orphan code we'd been carrying for forty phases. P109 rebuilt a README that had been 89 ADRs stale. None of that was visible from the outside until we wrote it down. The artifact under defense isn't the website builder we set out to build. It's the practice of telling the truth at the gate, fixing it in the next sprint, and moving on. That's the thing worth keeping.
